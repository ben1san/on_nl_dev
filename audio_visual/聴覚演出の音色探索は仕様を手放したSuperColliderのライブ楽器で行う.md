# 聴覚演出の音色探索は仕様を手放したSuperColliderのライブ楽器で行う

## 要約

音を作る作業を、コードを直して毎回音声ファイルを書き出す方式から、鳴らしたまま手元のつまみで音を変えられる方式に変えた。すでに固まっていた音の設計は一度脇に置き、白紙から積み直している。作業の中で、響きを広げるつもりで入れていた仕掛けが、切れ目なく鳴り続ける音に対しては逆に機械的な脈動しか生まないことが分かった。

## 道具をSuperColliderにした理由

`audio_visual/erasure_sonification_v5.py`は、ファイル全体を読み込んで全ブロックを一括計算し`.wav`へ書き出すオフラインのバッチ処理である。音を少し変えるたびにコードを直し、全体を再計算し、書き出し、聴き直す往復が必要で、つまみを回した瞬間に音が変わる感触が得られない。音色探索の本質は「まだ言葉にできていない音を耳で探す」ことなので、この往復の速さが他の何よりも優先する。

pyoを却下した。最終的にRaspberry Pi上のPythonへ合流させる観点ではpyoが有利で、探索段階で書いたシグナルチェーンがそのまま移植できるという利点がある。しかし鳴らしている音のパラメータをその場で書き換え続けるライブコーディングの対話性ではSuperColliderが明確に速く、探索フェーズに限れば移植コストを払ってでも往復の速さを取る価値があると判断した。[[research/視覚聴覚演出の実装材料と類似事例.md]]が未検証として残していた「SuperColliderとpyoの実装コスト・レイテンシ・MQTT連携との親和性を比較していない」という宿題に対する、探索フェーズに限定した部分的な回答にあたる。**Piへの移植コストは未見積もりのまま残っている。**

## 確定仕様を一旦適用しない判断

[[audio_visual/聴覚演出は回路クロック分周の純正律ドローンと連続グライドする記憶の声で構成する.md]]の仕様をSuperColliderへ移植したファイル(`erasure_sonification_live.scd`)は作ったが、そこから先へは進めず、何も持ち込まない白紙のスケッチ(`erasure_sonification_scratch.scd`)を別に立てて、正弦波1つから積み直している。

仕様は回路定数$R=117\,\Omega$・$C=71\,\text{nF}$から音程を導くという筋の通った導出を持ち、協和音程を選ぶ判断を経ずに純正律が得られるという美点がある。しかしその導出が正しいことと、出てきた音が聴くに値することは別の問題であり、耳で確かめる段階を踏まないまま仕様が固まっていた。白紙から積むのは、この飛ばした段階をやり直すためである。2つのファイルは併存させ、**どちらを採用するか、あるいは統合するかは未決**とする。

## 楽器の現在のかたち

汎用ボイス1種類を任意個並べる構成にした。波形は種類ごとに別々の音源を用意するのではなく、サイン波・ノコギリ波・パルス波・三角波・ノイズの5つを1つの音源の中に持たせ、数値のパラメータで切り替える。同時に鳴らせる数は定数1つで決まり、増やせば操作パネルの数も自動で追従する。各ボイスは周波数・音量・荒さ・フィルタの開き具合に加え、フィルタを自動で波打たせる速さと深さを持つ。

全ボイスの音は個別にスピーカーへ出さず、いったん専用の経路へ集めてから、歪み・エコー・リバーブの順に通す。3つともON/OFFと強さを個別に持ち、OFFのときは音をまったく変えずに素通りする。ほかに、高い音から一気に下がる単発のレーザー音を持つ。

## 持続音に空間を与えるのはリバーブだけである

これが今回いちばん実質的な知見であり、既存の設計の一部を否定する。

エコー(コムディレイ)は1つの反射を等間隔で繰り返すものである。人間の耳は規則的な繰り返しを即座に検出するため、等間隔の反復は空間ではなくリズムとして知覚される。ディレイ時間0.35秒なら毎秒2.9回、0.7秒でも毎秒1.4回の脈動になり、実際の試聴で「ヘリコプターのように機械的」と評された。ノイズ成分を通した場合はフラッターエコーとなり、金属的なばたつきに変わる。

さらに原理的な問題がある。ディレイがやまびことして聞こえるには、音に立ち上がりが必要である。本作の音は[[audio_visual/聴覚演出はノーバッファの連続グライド楽器として記憶の中身相関を担う.md]]の既定により切れ目のない持続音として設計されているため、遅れて返ってきた音が元の鳴り続けている音に埋もれてしまい、残るのは周期的なうねりだけになる。**持続音を前提とする本作において、エコーは空間を作る手段として原理的に使えない。**

空間はリバーブに担わせる。当初使っていたFreeVerbは部屋の大きさと減衰の値がコード内に固定されており、外から変えられるのは湿り具合だけで、尾も短い。これをGVerbへ差し替え、部屋の広さをメートル、残響長を秒で直接指定できるようにした。単発音を鳴らして録音し、減衰カーブを実測した結果が次である。

| 経過時間 | ピーク基準 |
|---|---|
| 1.0秒 | $-1.5$ dB |
| 3.0秒 | $-22.6$ dB |
| 5.0秒 | $-40.2$ dB |
| 7.0秒 | $-57.7$ dB |
| 7.5秒 | $-61.2$ dB |

設定は部屋の広さ60m・残響長7.5秒で、$-60$ dBまでの減衰時間は実測6.5秒だった。重要なのは秒数そのものより、dB値がほぼ一直線に下がっていることである。これは滑らかな指数減衰、すなわち本物の残響の尾の形であり、エコーが作っていた周期的な山と谷がどこにも現れない。なおFreeVerb側は実測しておらず、短いという判断はカタログ的な性格からの見積もりに留まる。

**既存仕様との矛盾がある。** [[audio_visual/聴覚演出は回路クロック分周の純正律ドローンと連続グライドする記憶の声で構成する.md]]はディレイ時間をブロック周期$\approx0.544$秒に設定している。演出値を持ち込まず回路由来の値を使うという筋は通っているが、持続音に適用する限り毎秒1.8回の周期的な脈動として聞こえる。回路との整合と聴感のどちらを取るかは統合担当を交えた確認が必要である。

## 左右の広がりは現状リバーブだけが作っている

全ボイスは同じ信号を左右チャンネルへ複製して出しており、定位はすべて中央にある。したがって左右の広がりはGVerbが残響を左右非相関に散らす分だけしか存在しない。ボイスごとに定位を与えるパンニングは未実装で、リバーブを上げても物足りない場合はここが最も効果の大きい手当てになる。

## この環境で踏んだSuperCollider固有の罠

SuperCollider 3.14.1(macOS・Apple Silicon)で、原因が分かりにくい形で作業を止めた事象を記録する。同じファイルを触る者が再び踏む可能性が高い。

| 事象 | 回避 |
|---|---|
| `Decimator.ar`がUGenグラフ構築中にハングし、エラーも出ずsclangが応答しなくなる | 手動の量子化演算で置き換える |
| `~R`・`~C`のような単一の大文字を環境変数名にするとコンパイルがハングする | 必ず複数文字の名前にする |
| `EZSlider`を`VLayout`へ直接追加すると`asView`が理解できないというエラーになる | `.view`を付ける。ただし付けても内部レイアウトが潰れてラベルも数値も見えなくなるため、素の部品で行を自作するほうが確実 |
| `ScrollView`のホイール操作が、カーソル下のスライダーの値変更と競合する | スクロールを使わずタブ切り替えで1画面に収める |
| Synthの`.isPlaying`でON/OFFを判定すると取りこぼし、多重起動して止められない音が残る | 言語側の変数で在否を管理する |
| `Score`で複数のSynthDefを同じ時刻に送るとレンダリング結果が無音になる。エラーも警告も一切出ない | scsynthのOSC受信バッファは32KB。同時刻のメッセージは1つのバンドルにまとめられるため、大きな定義を2つ以上置くと超えて丸ごと捨てられる。**定義は1つずつ別の時刻に送る** |
| `Array:includes`が、内容の等しいStringに対して`false`を返す | 同一性で比較しているため。Symbolへ変換してから比較する |
| `Decay2.ar`が「first input is not audio rate」で組み立てに失敗する | `Dust.kr`など control rate のトリガを渡している。`Decay2.kr`にするか、`Dust.ar`を使う |
| `Ringz`の周波数・減衰時間にオーディオレートの信号を渡すと無音になる | `T2K.kr`でトリガをcontrol rateへ落とし、`TExpRand.kr`等で1発ごとの値を作る |

最後の項目は特に危険で、押すたびに新しい音が積み上がり、古い音は参照を失って停止できなくなる。緊急停止(`s.freeAll`相当)を操作パネルに常設した。

後半の4項目はNRTレンダリング(`Score.recordNRT`)で踏んだもので、**症状がいずれも「無音のwavが書き出される」だけ**という点が共通する。エラーも警告も出ないため、層を1つずつ切り分けて描画し、どこで音が消えるかを二分探索するのが唯一の手立てになる。`audio_visual/render.scd`が`LAYERS`環境変数で層を切り分けられるようにしてあるのはこのためである。

## 未検証

音色そのものはまだ狙いに届いていない。試聴の評価は「無機質すぎて奥行きがない」「深みがない」「クリアさ・透明感がない」「各種の周期が一定で有機的でない」「低音が安定しすぎている」という段階にあり、目標として挙がっているやくしまるえつこ×真鍋大度のdimtaktとは隔たりがある。とくに周期の一定さと低音の安定は、うなり・非同期のゆらぎ・不安定さの導入という未着手の手当てが必要である。

このほか、確定仕様と白紙スケッチのどちらを採るかは未決、実データおよび実QRNGへの配線は未着手、Piへの移植方式(pyoへの書き直しか`scsynth`をPi上で動かすか)は未検討、ディレイ時間$0.544$秒の扱いは統合担当の確認待ち、パンニングは未実装である。
