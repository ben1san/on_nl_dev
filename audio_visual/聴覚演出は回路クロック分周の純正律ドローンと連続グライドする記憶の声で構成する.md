# 聴覚演出は回路クロック分周の純正律ドローンと連続グライドする記憶の声で構成する

## 要約

装置が消去処理をしている間だけ、切れ目のない持続音が鳴り続ける。音が鳴り始めたり止んだりする瞬間は一度もなく、消去されているデータの性格に応じて響きの明るさと音の高さだけがゆっくり移り変わる。和音の構成は装置の回路が刻む時計の速さを整数で割ることでひとりでに決まっており、たまたま協和音程になっている。

この仕様は5回の試作（v1〜v5）を経た現時点の設計。判断理由・却下した案は[[audio_visual/聴覚演出のPlay-Destroy式劣化はブロック単位の使い捨てグレインでノーバッファ制約と両立する.md]]を参照。実装は`audio_visual/erasure_sonification_v5.py`。

## 回路から決まる数値

[[classical_erasure/components.md]]0節の確定値（$R=117\,\Omega$、$C=71\,\text{nF}$）から次が計算できる。

| 量 | 値 | 意味 |
|---|---|---|
| $\tau=RC$ | $\approx8.307\,\mu s$ | 1遷移の時定数 |
| 1サイクル（$16\tau$、4相） | $\approx132.9\,\mu s$ | 投入→消去→攪拌→鎮静の1周 |
| $f_\text{cycle}=1/16\tau$ | $\approx7523.8\,\text{Hz}$ | 8bit並列なので1サイクル＝1バイト処理 |
| ブロック長（暫定） | 4096 byte | Pi→Picoへの実ストリーミング単位 |
| ブロック周期 | $\approx0.544\,\text{s}$ | パラメータ目標値の更新間隔。**発音間隔ではない** |
| ディレイ時間 | $\approx0.544\,\text{s}$ | ブロック周期そのもの |

### 整数分周がそのまま純正律になる

$f_\text{cycle}$を整数で割った各周波数は、互いに$2{:}1$・$3{:}2$・$4{:}3$の整数比を持つ。つまりオクターブと完全4度・完全5度だけで構成された開いた響き（オルガヌム的な響き）が、協和音程を選ぶという判断を経ずに回路定数から自動的に得られる。

| 分周 | 周波数 | レイヤー音量 |
|---|---|---|
| $f_\text{cycle}/64$ | $117.56\,\text{Hz}$ | 0.85 |
| $f_\text{cycle}/48$ | $156.75\,\text{Hz}$ | 0.45 |
| $f_\text{cycle}/32$ | $235.12\,\text{Hz}$ | 0.80 |
| $f_\text{cycle}/24$ | $313.49\,\text{Hz}$ | 0.40 |
| $f_\text{cycle}/16$ | $470.24\,\text{Hz}$ | 0.70 |
| $f_\text{cycle}/12$ | $626.98\,\text{Hz}$ | 0.28 |
| $f_\text{cycle}/8$ | $940.47\,\text{Hz}$ | 0.16 |

$f_\text{cycle}/16\approx470.24\,\text{Hz}$は平均律のA#4から約$+15$セントにあたるが、これは意図してチューニングした値ではなく回路定数がもたらす「見つかった音程」である。

## 離散的な発音を一切持たない

**この仕様の最も重要な制約。** アタックを持つ音、減衰して消える音、単発で鳴る音は一切使わない。ブロックごとに算出される統計量は「音を鳴らすトリガー」ではなく「鳴り続けている音のパラメータ目標値」として扱い、ブロック周期ごとに更新される目標値へsmoothstep補間で滑らかに移行させる。回路由来のタイミング（$0.544\,\text{s}$周期）は保たれるが、耳には切れ目のない連続音として届く。

これは[[audio_visual/聴覚演出はノーバッファの連続グライド楽器として記憶の中身相関を担う.md]]が定めた「ブロックごとに新しい音を都度トリガーするのではなく、常時鳴り続ける一本のオシレーターを、ブロックが来るたびに次の目標値へポルタメントで滑らかに追従させる」という既定に従うものである。

## 構成する4つの層

### 純正律ドローン床 — 装置自身の身体（中身に依存しない）

上表の7つの分周を重ねた持続音。各レイヤーは3〜4声のユニゾンで、16個のハーフセルが持つコンデンサ容量公差に由来する微小なデチューン（実効幅$\approx56$セント）を与える。セルごとに$\tau=RC$が僅かに違うため各セルの周波数がもともと揃っていないという事実に基づくが、実効幅は音楽的な理由でスケールした値である（後述の未検証を参照）。$0.043\,\text{Hz}$と$0.017\,\text{Hz}$という非整数比のLFOで緩やかに揺らし、有機的な質感を持たせる。

$P=1.23\,\text{W}$という総散逸電力は消去処理中ずっと一定なので、ドローン床の音量もセッション中は変化させない（クレッシェンドは実測に基づかない演出になる）。

### 記憶の声 — 記憶データ$d$（連続グライド）

[[classical_erasure/architecture.md]]4.4節の投入相$(0,0)\to(d,\bar d)$が保持する記憶データ$d$を表す、常時鳴り続ける1本の声。

- 音高：ブロックのシャノンエントロピー$H(d)$を主軸に$（f_\text{cycle}/16)\cdot2^{(H-6)/4}$で写像し、平均バイト値で$\pm$約35セントの微細な揺らぎを加える。**発音せず、目標値へ向かって滑らかにグライドし続ける**
- 音色：フォルマント共鳴を$620\,\text{Hz}$・$1450\,\text{Hz}$と高めに置き、籠らせない
- 純度：$H(d)$から算出する「純度」が、声の音量と上方レイヤーの開き具合を支配する。**記憶の性格が音の明るさとして出る**

実データ（日本語テキスト等）で約3.4半音の幅を連続的に動く。既に乱数で上書きされた領域ではエントロピーが理論上限（8 bits/byte）に張り付くため声は動かなくなる——**この動きの消失そのものが消去の証拠になる。**

### きらめき — 安らかさのための空気感

$f_\text{cycle}/4\approx1880\,\text{Hz}$に薄く重ねる高域成分。記憶の純度に連動し、$0.021\,\text{Hz}$のごく緩やかな呼吸で明滅する。籠りを避け、開けた印象を作るための層。

### 乱数テクスチャ — 乱数$r$（ひとつづきの息）

攪拌相$(0,0)\to(r,\bar r)$が保持する乱数$r$を、$r$の実バイト列を$400\,\text{Hz}$〜$3\,\text{kHz}$に帯域制限した連続テクスチャとして重ねる。$r$は最大エントロピーであり音高を持てないため、旋律的な要素としては扱わない。消去が進むほど気配が増す（セッション中で唯一の進行感）。

残響を通さずドライに保つことで、遠い響きの中に「熱源の近さ」を対比として置く。鎮静相（$r$の放電）こそが[[classical_erasure/architecture.md]]4.6節のいう真のランダウアー消去＝実際に発熱している瞬間なので、$r$が近く聞こえるのは演出ではなく物理的に正しい。

## 空間処理

| 項目 | 値 | 根拠 |
|---|---|---|
| 残響長 | $7.5\,\text{s}$ | 遠い広がり。残響自体がエネルギーの不可逆な散逸であり主題と同型 |
| 残響の帯域 | $120\,\text{Hz}$〜$5.2\,\text{kHz}$ | 低域の濁りを削り、高域を開いて籠りを避ける |
| ディレイ時間 | $\approx0.544\,\text{s}$ | ブロック周期そのもの（回路由来） |
| ステレオ | L/R非相関のIR | 横の広がり |

## 劣化（Play/Destroy的な不可逆性）

生成された音は不可逆な劣化処理を経て鳴り、次のブロックへ何も持ち越さない。劣化はビットクラッシュ（有効ビット数を劣化度$p$に応じて16bitから最小4bitまで減らす量子化）による**音色変化としてのみ**効かせる。サンプル&ホールド型のドロップアウト（プチプチというノイズ）は使わない——連続音の安らかさを壊すため。連続的なホワイトノイズも使わない（[[audio_visual/聴覚演出はノーバッファの連続グライド楽器として記憶の中身相関を担う.md]]の試聴で「耳障りな"サー"」と既に判定済み）。

劣化度$p$は`furnace/erase_progress`（0.0→1.0）を使う。**ただしこれは回路の実測に対応した挙動ではない**（各ブロックは物理的に等しく完全に消去されており、終盤のブロックが序盤より強く壊されている事実はない）。維持するか一定にするかは未決定。

## 儀式フローとの対応

| フロー（[[concept/functional_req.md]]2節） | 状態機械（FR-10） | 光（[[enclosure/enclosure_design.md]]3節） | 音 |
|---|---|---|---|
| ①〜④ 準備・手放し | 投入→選択→転写→原本消去 | 完全消灯 | 無音 |
| ⑤〜⑥ 乱数生成・検証 | 乱数生成中→検証中 | 低輝度・不規則な明滅 | 未設計 |
| ⑦ 点火 | 点火 | セル単位のノイズ状明滅 | **全層が緩やかにフェードインし、以降セッション中ずっと途切れず鳴り続ける。記憶の声が$H(d)$に追従して動き、乱数テクスチャが徐々に増す** |
| ⑧ 発熱・視覚・聴覚による体感 | 完了 | 全セル同時ストロボ→NTC冷却時定数で減衰 | **NTC冷却時定数（$\approx8\,\text{s}$）に同期してフェードアウト。**残響の尾が自然に残り、光・熱と余韻が揃う |
| ⑨ 待機へ戻る | 待機 | 完全消灯 | 無音に戻る |

セッションの実時間長は投入ファイルサイズに依存する（1MB≈140秒は一例）。

## リアルタイム生成の原則

音は必ず「今流れているブロックだけを見て、その場で合成する」ライブプロセスとして実装する。事前レンダリングは原理的に不可能である——未来のブロックを先読みすれば[[classical_erasure/architecture.md]]8節のノーバッファ制約を破ることになるため。音声合成はPi上で動き、Pi→Picoへ流れる実ブロックに便乗して統計量だけを導出し、使った直後にブロックも統計量も破棄する。実装候補（pyo・SuperCollider・Tone.js等）は[[視覚聴覚演出の実装材料と類似事例]]を参照。

## 未検証

実機（Raspberry Pi/Pico/MQTT）とは未接続で、消去対象データはボールト内の実markdown、乱数は疑似乱数で代替している（本物のQRNG出力ではない）。ユニゾンデチューンの実効幅（$\approx56$セント）は、X7Rコンデンサの実際の公差（$\pm10\%$）をそのまま適用すると1オクターブ以上ばらけて使用に耐えないため音楽的な理由で縮小した値であり、他の数値（$470.24\,\text{Hz}$、$0.544\,\text{s}$）と違って実測の増幅ではない。ブロック長4096 byteは儀式的テンポを優先した暫定値。$r$の実バイト列を音声バッファへ載せることが「$r$をいかなる場所にもバッファ保持してはならない」制約にどう抵触するかは統合担当を交えた確認が必要。⑤〜⑥（乱数生成・検証フェーズ）の音は未設計。劣化度$p$の進行を維持するか一定にするかは未決定。エントロピーから音高への写像係数は暫定値で音楽的妥当性は未検証。人間による試聴での最終判断は途中段階にある。既存の[[audio_visual/聴覚演出はノーバッファの連続グライド楽器として記憶の中身相関を担う.md]]が到達したdimtakt型楽器（機嫌・交信音という自律レイヤーを持つ）と本仕様のどちらを採用するか、あるいは統合するかはチームでの判断が必要。
