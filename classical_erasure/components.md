 部品表 — 焼却レジスタ構成

## 0. 前提となる設計パラメータ

先に回路方式を確定させておきます。**相補容量セル + TC4427直接駆動**。専用スイッチを置かず、TC4427（デュアルMOSFETドライバ）の出力段そのものが充放電を担う構成です（旧版は74HCT595直接駆動でしたが、駆動力不足でビット数が不必要に縛られていたため変更しました。経緯・導出は[[cell_driver_choice]]参照）。

1セル（1ビット）= 相補な2組の $(R, C)$。1サイクルは4遷移:

$$(0,0) \to (d,\bar d) \to (0,0) \to (r,\bar r) \to (0,0)$$

各遷移で**必ずちょうど1個のコンデンサが充電または放電**するので、$d$ と $r$ の値によらず散逸は一定。プリチャージ対称性が回路トポロジーだけで成立します。

| パラメータ | 値 | 備考 |
|---|---|---|
| 駆動段 | **TC4427**（デュアルMOSFETドライバ、DIP-8、2ch/個） | 1個で1bit分（$C_b$・$\bar{C_b}$）を賄う |
| 動作電圧 $V$ | **12 V** | TC4427は4.5–18 V対応。18 Vまで伸び代あり（下記） |
| セル容量 $C$ | **68 nF**（ポリエステルフィルム ±5% 50V） | E系列に71 nFは存在しない。総発熱量には影響しない（下記「重要な性質②」） |
| 直列抵抗 $R_{ext}$ | **120 Ω** 1/4 W | ドライバ $R_{on}$ と直列。抵抗をアルミ板に実装するという設計原則上、下げられない |
| ビット数 | **8 bit 並列** | **16ハーフセル**。Picoの空きGPIOに直結でき、シフトレジスタが不要（[[cell_driver_choice]] 3節） |
| 時定数 $\tau$ | **9.358 µs（実測）** | 充電9.322 / 放電9.394 µs、非対称度0.8%（下記「実測値について」） |
| 1相の長さ | $4\tau$ = **37.4 µs** | MicroPythonの`sleep_us(30)`で実測37.5 µs（4.01τ） |
| $\alpha$ | **18.9 µJ/bit** | $2CV^2\tanh(2)$。4τ打ち切りによる3.6%減を含む（下記「重要な性質③」） |
| サイクル周波数 | **6.68 kHz** | $1/(16\tau)$ |
| 総散逸 | **約1.0〜1.1 W**（うち掌側 ~0.95〜1.0 W） | 幅は$R_{on}$の不確かさによる |
| スループット | 53 kbit/s ≈ 6.7 kB/s | 1 MB を**約157秒** |

**実測値について**: $\tau$は等価時間サンプリング（同じ遷移を繰り返し、測定タイミングを1 µsずつずらす）でPico自身のADCから取得した。決定係数は充電0.9997・放電0.9999で、きれいな単一指数になっている。**充放電の非対称度0.8%**は、TC4427のプルアップ側とプルダウン側の$R_{on}$がほぼ等しいことを意味し、4相すべてを同じ待ち時間で回せる根拠になる。

ただしこの測定は**5V駆動**で行った。$R_{on}$は電源電圧に依存するため、12Vでは$\tau$がやや短くなる。$\tau=RC$からは$R$と$C$を分離できず（$C=68$ nFなら$R=138\,\Omega$、$R=127\,\Omega$なら$C=74$ nF）、総散逸$P$は$R$だけで決まるため、上表の1.0〜1.1 Wという幅はここから来ている。確定にはINA260の実測が要る（4節）。

**重要な性質①**: RC充放電の散逸エネルギーは $\frac12 CV^2$ で、**$R$ の値に一切依存しません**。つまり抵抗の誤差が熱量に影響しない。$\alpha$ の精度は $C$ の精度だけで決まり、16個の平均で誤差は $1/\sqrt{16}\approx25\%$ に落ちます（INA260実測で較正する前提なので許容範囲。[[cell_driver_choice]] 2節）。フィルムコンデンサは初期公差が±5%なので、この誤差はさらに小さくなります。

**重要な性質②（総発熱量は$C$に依存しない）**: 各フェーズで確実に$4\tau$待って完全充放電する設計（サイクル時間$=16\tau=16RC$）なので、サイクル周波数は$f=1/(16RC)$と$C$に反比例して決まる。総散逸電力は

$$P = N_{bit}\times\alpha\times f = N_{bit}\times 2CV^2\times\frac{1}{16RC} = \frac{N_{bit}V^2}{8R}$$

となり、**$C$が式から消える**。$C$を大きくしても総発熱量は増えず、サイクルが遅くなる（スループットが落ちる）だけ。総発熱量を左右できるのは実質$N_{bit}$（＝基板規模）と$V$のみ。旧74HCT595（5V上限）では$V$に伸び代がなかったが、**TC4427（4.5–18V）は$V$が実用的なレバーになる**。$R_{ext}$は下げられない（[[cell_driver_choice]] 2.5節）。（導出は[[architecture]] 7節にも記載）

**重要な性質③（$\alpha=2CV^2$には打ち切り補正が要る）**: 1相を$4\tau$で打ち切ると充電は98.17%までしか進まないため、$\alpha=2CV^2$は厳密には成立しない。相の長さを$k\tau$として定常状態を解くと、充電後電圧$V_b$と残留電圧$V_r$が$V_b+V_r=V$を満たすため散逸は$\frac12C(V_b-V_r)$の形になり、

$$\alpha = 2CV^2\cdot\tanh(k/2)\qquad(k=4\text{で}0.964、k=5\text{で}0.987、k=6\text{で}0.995)$$

**この補正は対称性を崩さない。** 散逸の式に中身に依存する項が現れないうえ、オール0とオール1は$C_b \leftrightarrow C_{\bar b}$の鏡像関係にあるため、ペア単位で完全に打ち消し合う。不完全充電に対しても相補ペアという構造が効いていることになる。総散逸も同じ係数がかかり、$P = \dfrac{N_{bit}V^2}{2kR}\tanh(k/2)$ となる。

⚠️ **ビット数（8bit）・$C$（68 nF）・$V$（12 V）は固定します。** 発熱が足りない場合の優先順位は、①$V$を18Vまで上げる（約1.05W→約2.4W、部品・基板は無変更。ただし抵抗は1/4W必須）②接触窓の面積を調整③ビット数を増やす、の順です（詳細は[[cell_driver_choice]] 2.5節）。**接触窓のサイズは12 mm角を設計値として採用する。**

（逆方向——現行値のままでも42℃ハードカットに対して発熱が「too much」になる問題については3節・4節を参照。4節のデューティ制御を実装する前提でも、この優先順位自体は変わらない。）

**構築方針（単段構成に一本化）**: 量産発注は行わない。回路構成（TC4427直接駆動・8bit・16ハーフセル）はそのまま、実装はユニバーサル基板＋生アルミ板＋手ハンダ（R・Cペアを直列に組み、R本体のみ熱伝導両面テープでアルミに貼る「案B」）に一本化し、これを本番発表用の最終構成として組み立てる（1〜3節）。JLCPCBへの発注を挟まないため、今週中の部品調達だけで完成まで進められる（8節）。

## 1. 情報層（制御）

| 品目             | 型番                         | 数量        | 概算     |
| -------------- | --------------------------- | --------- | ------ |
| マイコン           | Raspberry Pi Pico 2         | 2（予備込）    | ¥1,600 |
| セルドライバ         | **TC4427** DIP-8            | 10（8＋予備2） | ¥2,000 |
| デカップリング        | 100 nF（リード品）                | 10        | ¥100   |
| バルクコンデンサ（12V系） | 10 µF 電解                    | 3         | ¥150   |
| 制御基板           | **ユニバーサル基板**（穴あき、汎用、即日入手可） | 1         | ¥300   |

制御基板はユニバーサル基板に一本化し、これを最終構成として使う。部品は手ハンダの点対点配線で実装する。FR4カスタム基板の発注は行わない。

**なぜTC4427か**：74HCT595はセルを直接駆動するには弱すぎ（5V・16.7mA/ch）、ビット数がそれだけで64に縛られていました。TC4427（4.5–18V・ピーク1.5A）に切り替えることで、同じ（実際にはそれ以上の）発熱をわずか8bitで賄えます。導出は[[cell_driver_choice]]を参照。Picoの3.3V GPIOで直接駆動できることはデータシートで確認済み（[[circuit_schematic]] 0節）。

**Picoの役割**: 4相タイミングを生成し、16本（8bit×2ハーフセル）のGPIOでTC4427の入力を直接駆動します。**シフトレジスタによるシリアル展開は不要**（Picoの空きGPIOで足りる規模）。この構成が使えるのは概算9〜10bitまでで、それ以上ビット数を増やす場合は再びシフトレジスタが必要になります（[[cell_driver_choice]] 3.5節）。

**GPIOの書き込み方は自由に選べません。** 実測すると、`Pin.value()`で1ピンずつ書く方式は2ピンで8.24 µs/相かかり、16ピンに拡張すると概算55〜66 µs/相となって設計値37.4 µsを超過します。**SIOレジスタ（`GPIO_OUT`、RP2350では`0xd0000010`）へ32ビットワードを1回書く方式**なら、ピン数に依存せず3.32 µs/相で済みます。16ピンが同時に切り替わる点も、1ピンずつずらして書くより相補ペアの対称性の観点で素直です。

**PIOはスループットのためには不要でした。** [[architecture]] 3.1節は「PIOによる決定論的タイミング生成」としていますが、素のMicroPython＋SIO書き込みで`sleep_us(30)`→37.5 µs/相（4.01τ）と設計値に届きます。PIOの価値は速度ではなくジッタの排除にあり、組み立ての律速にはなりません。なおジッタは**遅れる方向なら無害**（$W=\frac12CV^2$は遷移時間に依存しない）ですが、**4τより短い相が混じると充電が完了せず残留電荷が履歴に依存し始める**ため、短くなる方向のずれだけは避ける必要があります。

**ピン割り当て**: GP0〜GP15＝16ハーフセル駆動、GP16/GP17＝Piとの UART0、GP18＝コンパレータ出力モニタ、GP20/GP21＝INA260のI2C、GP26/GP27＝NTC読み取り（ADC）。

穴単位の実装配置（Picoソケット・TC4427×8・2つのコネクタの座標と全配線）は[[情報層基板の実装配置]]を参照。

⚠️ **RP2350のエラッタE9**: 入力＋内部プルダウンでパッドが浮いていると、入力バッファがラッチして約2.1Vに張り付きHIGHと読めてしまいます。ファームウェアで内部プルダウンに依存した判定を書かないこと（外部プルダウンは8.2 kΩ以下）。RP2040には無い、RP2350固有の問題です。

**Raspberry Pi**: 所持品。MQTT受信 → tmpfs（`swapoff -a` 必須）→ UART/SPIでPicoへ。不揮発媒体に一切触れさせないこと。

## 2. 消去セル（核心部）

| 品目      | 仕様                                    | 数量  | 概算   |
| ------- | ------------------------------------- | --- | ---- |
| セルコンデンサ | **68 nF 50 V ポリエステルフィルム ±5%**（リード品） | 20  | ¥500 |
| 直列抵抗    | **120 Ω 1/4 W**（axialリード品）           | 20  | ¥500 |

**フィルムコンデンサを採用します（旧版はX7Rを指定していた）。** X7RはDCバイアスで容量が落ちるため、旧版は「容量変動は相補ペアの両側で同一に効くので対称性は保たれる。$\alpha$の絶対値のずれはINA260で較正する」という注記を必要としていました。ポリエステルフィルムはDCバイアスによる容量低下がほぼ無く温度特性も安定なので、**この注記自体が不要になります**。初期公差も±5%（X7Rは±10〜20%）と良く、$\alpha$がセッション中に動かないぶんINA260較正の信頼性が上がります。

ピン番号レベルの詳細回路図（TC4427の実ピン配置・入力しきい値の確認込み）は[[circuit_schematic]]を参照。

**実装方法（案B、最終構成）**: RとCを直列にハンダ付けしたペアを16組作る。R本体のみ熱伝導両面テープでアルミ板に貼り（発熱するのはRのみ、0節参照）、Cはアルミに接触させず宙に浮かせる。各ペアの両端（TC4427出力側・GND側）をリボンケーブルでユニバーサル基板まで引き出す（16〜17本、3節参照）。銅パターンのエッチング・貼付は不要。axialリード抵抗・リードセラミックコンデンサの方が手ハンダとテープ固定に向く。

**抵抗のワット数について**：1本あたり平均電力は12V動作時で約61 mW。$V$を18Vまで上げる運用を想定すると約137 mWとなり1/8W定格（125 mW）を超過するため、**1/4Wを採用**（18Vでも定格の55%で収まる）。焼損マージンの試算は[[cell_driver_choice]] 2.5節を参照。

**ピーク電流について**: 1チャネルあたりのピーク電流は$V/R\approx12/130\approx92$ mA。TC4427のピーク定格1.5Aに対して約6%と余裕があり、74HCT595のときのようなGNDピン定格の逼迫は発生しません。

**接続部はハンダ付けとする。** リードを接触させてテープで巻く圧着接触は採用しない。この装置は消去のたびにプレートを30→42℃へ往復させる、つまり熱サイクルが正常動作であり、これは圧着接触の接触抵抗を劣化させる最悪の条件にあたる（加えて酸化と粘着剤のクリープ）。接触不良でセルが1つ開放になっても装置は何事もなく動き続け、**そのビットだけが消去されないまま検出されない**——「データが物理的に破壊された」ことを主張する装置にとって、これは受け入れられない故障モードになる。リードをねじってからハンダを流し、収縮チューブで絶縁する。

## 3. 熱層（接触プレート、筐体スタック最下段）— 生アルミ板（最終構成）

| 品目 | 仕様 | 数量 | 概算 |
|---|---|---|---|
| **アルミ板** | 生板 **t0.3 mm を3枚重ね（合計0.9 mm）**、**35×40 mm**に切り出し | 3 | ¥1,000 |
| ピンヘッダ／ソケット | 2×10ピン、ユニバーサル基板と直結 | 2 | ¥300 |
| 配線 | リボンケーブル 20芯 300 mm（16〜17本使用、残りは予備） | 2 | ¥400 |
| 熱伝導両面テープ | R本体のアルミ板貼付用 | 1 | ¥800 |

**実装（案B、最終構成）**: 3節の通り、R・Cを直列ハンダ付けしたペア16組を作り、各ペアのR本体だけを熱伝導両面テープでアルミ板に貼る（Cはアルミに接触させない）。各ペアの両端をリボンケーブルでユニバーサル基板まで引き出す。銅パターンのエッチング・貼付は不要（発熱源はRのみのため、Cとの電気的接続は単純な配線で足りる）。

**部品（R+Cペア）は板全面に分散配置してよく、接触窓の近くに寄せる必要はない**。アルミの熱拡散率は概算$a\approx97\,\text{mm}^2/\text{s}$、拡散長$L\sim\sqrt{at}$で見積もると、消去セッションの時間スケール（数秒〜1分程度）で$L$は板サイズを上回ります。つまり数秒〜十数秒で板全体がほぼ均一な温度に達するため、個々の抵抗の位置は無関係です。窓が制御しているのは熱の**発生場所**ではなく**逃げ道**（断熱していない箇所からしか外へ出られない）です。

**⚠️ ただしこの議論が成立するのは板が十分厚い場合だけです。** 上の拡散長の話は温度が均一化するまでの**時間**の話で、定常的に熱が流れている状態での**温度勾配**は別問題です。発熱は板全面で起き、熱は12 mm角の接触窓へ集まって外へ出るため、板の中には定常的な横方向の熱流があります。この経路の断面積は板厚に比例するので、薄いと**窓が板の他の部分より冷たくなります**。

窓の周囲（4辺×12 mm）を断面とし、経路長を約8 mmとして概算すると：

| 板厚 | 横方向の熱抵抗 | 板と窓の温度差 |
|---|---|---|
| 0.3 mm | 2.8 K/W | **約3.0 K** |
| **0.9 mm（採用）** | 0.93 K/W | 約1.0 K |

プレート40℃・掌34℃で駆動温度差は6 Kしかないため、3 Kの損失は体感を半分近く削ります。**t0.3 mmの単板は使えません。** 入手した0.3 mm材を3枚重ね、層間を熱伝導両面テープで貼り合わせて0.9 mmとします（空気層が挟まると下層へ熱が伝わらないため、貼り合わせは必須。貼り合わせ面は全面なので熱抵抗は0.3 K/W程度と無視できます）。

**重ねる理由は機械的にもあります。** 0.3 mm単板の35×40 mmは掌で押すと目に見えて変形します。剛性は板厚の3乗に比例するので、3枚重ねで27倍になります。参加者が掌を当てる面である以上、たわみは体験を損ないます。

**熱容量**は35×40×0.9 mmでの直接計算（密度2.70 g/cm³、比熱0.897 J/gK）で**約3.05 J/K**。室温30℃から42℃まで12 K上げるのに要する時間は放熱を無視して約37秒で、1 MBあたり157秒のセッションに対して十分速い。4節のデューティ制御パラメータはこの値を前提に設定する。

**⚠️ 熱伝導テープは板の全面に貼ること。** アルミは導体です。抵抗の胴体は塗装で絶縁されていますが、32本のリードは裸で、どれか1本でも板に触れるとセル同士が短絡します。テープは絶縁体なので、抵抗の下だけでなく全面を覆っておけば裸線が触れても短絡しません。抵抗直下のテープ厚は変わらないので熱性能への影響もありません。

**接触窓（底面）**: 0節の通り**12 mm角**を採用する。残り全面を断熱材で覆う。**露出面は天面ではなく底面**とし、筐体に脚を付けて浮かせ、参加者は底面から手を差し込んで触れる構成にする（「捧げる」動線とは切り離す。詳細は[[enclosure_fit_review]]参照）。これをやらないと定常温度が室温+数K程度にしかならず、掌より冷たいままです。ここが設計上いちばんシビアな点です。

**逆方向の制約（42℃ハードカットとの競合）**: 掌＋断熱経由の実効放熱は、プレートが42℃に達した時点でも概算0.6〜0.8 W程度（掌側熱伝達係数を200 W/m²K、12 mm角窓、皮膚深部34〜35℃と仮定。断熱漏れ+0.2〜0.3 W込み）にしかならず、掌側供給の約0.95〜1.0 Wに届きません。つまり**プレートは42℃で定常しません**。放置すればハードカットに先に当たり、$C_{th}=3.05$ J/K前提で**開始後およそ60〜90秒でハードカットに到達**します（1 MB ≈ 157秒のセッションに対して途中でセル電源が落ちる計算）。安全設計としては正しく機能している姿ですが、これを前提にせずデューティ制御なし（4節参照）で運用すると、①LM393のチャタリング②実効スループットの低下（デューティ制御されて157秒に収まらなくなる）③「発熱＝消去」という主張に対し消去クロックが温度制御に従属する構図になる、の3つが起きます。掌側熱伝達係数（200 W/m²K）は接触圧・発汗で50〜300 W/m²K程度まで動きうる最重要の未知数であり、この不確実性は4節の安全回路（LM393ハードカット＋ヒステリシス、40℃デューティ制御）で吸収する前提とする。本番運用前に実機へ手を当てた短時間の動作確認だけは行うこと。

| 品目     | 型番                          | 数量  | 概算     | 用途                        |
| ------ | --------------------------- | --- | ------ | ------------------------- |
| 電力計    | **INA260 ブレークアウト**          | 1   | ¥1,800 | $\int VI\,dt$、12 Vセル電源に挿入 |
| サーミスタ  | **103AT-11**（NTC 10 kΩ B=3435） | 5   | ¥500   | アルミ板上2、室温1                |

| 基準電圧   | **10 kΩ 半固定抵抗（トリマ）**        | 3   | ¥300   | 分圧基準。TL431から変更（下記）        |
| 正帰還抵抗  | 100 kΩ                       | 2   | —      | ヒステリシス2〜3 K               |
| 遮断素子   | Pch MOSFET（IRF9540等）        | 2   | ¥400   | セル電源のみ遮断                  |

**安全系はファーム経由にしないこと。** NTC → コンパレータ → PchMOSFETのゲート、というハードウェアのみのループで12 Vセル電源を切ります。Picoがハングしても効く経路を確保する。

**基準電圧はTL431ではなく分圧とする。** NTCを分圧で読む以上、ノード電圧は電源電圧に比例します。基準も同じ電源からの分圧にすれば両方が同率で動き、**電源変動があっても閾値温度が動きません**（レシオメトリック）。TL431は絶対値2.495 Vを作るため、逆に電源が振れると閾値がずれます。42℃付近の感度は12 V駆動で約94 mV/Kなので、電源が5%振れるだけで見かけ上2 K以上ずれる計算になり、ヒステリシス幅（2〜3 K）と同オーダーの誤差になってしまいます。NTCを定電流駆動するならTL431が正解ですが、分圧駆動では分圧基準の方が精度が出ます。

トリマにするのは、NTCのR25・B定数の公差があるため固定抵抗で42.0℃を狙うのが現実的でないからです。現物合わせで調整できることが実質的に必須になります。

**ヒステリシスは100 kΩの正帰還抵抗で得ます。** トリマ中点のテブナン抵抗2.5 kΩに対し$\Delta V = V_{swing}\cdot R_{th}/(R_{th}+R_{fb})$で、12 V系なら約3.1 K。プルアップ電圧と電源電圧が等しければ感度も同率でスケールするため、この値は電源電圧に依存しません。

**⚠️ オープンコレクタの直結はワイヤードANDです。** アルミ板上の2個のNTCで冗長化する場合、「過熱＝出力HIGH（解放）」という極性のまま2つの出力を直結すると、**両方が過熱を検知して初めて遮断**される回路になり、冗長化どころか安全性が下がります。真のOR冗長（どちらか一方の検知で遮断）にはインバータ段（トランジスタ1個＋抵抗2本）を挟む必要があります。1センサ構成のままにするか、インバータ段を足すかは未決定。

**NTCは2系統に分けます。** ハード安全ループを12Vで駆動するとノードも12V系になり、そのままPicoのADCには入れられません（分圧が必要で、しかも比が電源変動の影響を受ける）。

| NTC | 電源 | 載る基板 | 役割 |
|---|---|---|---|
| #1（アルミ板） | **12 V** | 安全層 | ハード安全ループ専用。コンパレータ→MOSFET。Picoは関与しない |
| #2（アルミ板） | **3.3 V** | 情報層 | Picoの40℃デューティ制御用（GP26） |
| #3（室温） | **3.3 V** | 情報層 | 室温補正（GP27） |

3.3V側の2本は**Picoの真横で分圧を完結させます**。安全層基板に置くと3.5kΩの高インピーダンスなアナログノードをリボンケーブルで往復させることになるためで、穴単位の実装は[[情報層基板の実装配置]]にあります。**どちらもNTCを下（AGND側）、10kΩを上（3.3V側）**に置き、断線時にノードが3.3Vへ張り付いて「熱い」と読める向きにします（デューティを絞る側＝安全側に倒れる）。安全層のNTC#1が上に付いているのは、あちらに断線専用のコンパレータがいるためで、向きの違いには理由があります。

Pico側を3.3 Vで駆動すると、ADCの基準電圧と分圧の電源が同じになるため完全にレシオメトリックになり、電源変動の影響が原理的に消えます（42℃でノード1.153 V、分解能0.03 K）。過電圧の心配も無くなり、ハード側は12 Vで完全に独立するので[[architecture]] 8節の「安全系はハードウェアのみで完結させる」がより厳密に守られます。

**正帰還抵抗で2〜3 Kのヒステリシスを必ず入れること。** 3節で見た通り、定常放熱（掌＋断熱経由、42℃到達時点で概算0.6〜0.8 W）が掌側供給の約0.95〜1.0 Wに届かないため、ヒステリシスなしのコンパレータだと42℃近傍で高速にON/OFFを繰り返します（チャタリング）。

**ソフト側の閾値40 ℃での温度制御は「推奨」ではなく必須です。** 上記の熱収支により、デューティ制御なしで運用するとプレートは42℃で定常せずハードカットに先に到達し、1 MB（約157秒）のセッション途中でセル電源が落ちます。Pico側でNTC読み取り→40℃付近を狙ってサイクル間にアイドル時間を挿入する疑似サーモスタット制御を必須の実装項目とし、ハードカット（42℃）は本来の「最後の砦」に戻してください。アイドル時間はサイクルの中身に依存しないため、相補ペアの対称性（[[architecture]]の設計不変条件）は崩れません。**ただし挿入するのはサイクルとサイクルの間だけで、1相を4τより短くしてはいけません**（0節「重要な性質③」参照）。

**INA260の測定範囲**: セル駆動の12 V系のみに入れます。TC4427駆動自体の消費（データ依存の微小な非対称、全体の~1%）も含まれますが、これは3パターン重ねの実験で検証できる量です。

## 8. 組み立て順序

原則は**「不可逆な工程を後ろに回す」「1個作って検証してから残りを作る」**の2点。

| 順 | 工程 | 検証方法 |
|---|---|---|
| 1 | **制御基板**（Picoソケット＋TC4427×8＋デカップリング） | Picoから16本を順に駆動し出力を確認 |
| 2 | **R-Cペア16組の製作** | **1組ずつτを実測して検品**（下記） |
| 3 | **熱層**：アルミ3枚貼り合わせ→R本体を貼る | ⚠️ 不可逆。2の検品後に実施 |
| 4 | **安全層** | 別基板で単体検証。NTCを加熱してトリップ点・復帰点・ヒステリシス幅を実測 |
| 5 | 12V化 → 筐体（5節） → 実機に手を当てた確認 → 本番 |

**ハンダ付けは背の低い部品から。** 部品面を下にして机に置き裏からコテを当てるのが基本なので、先に背の高い部品（バルクコンデンサ11 mm、ピンヘッダ8 mm）を付けると基板が傾いてICが斜めに付きます。ICソケット（5 mm）→ヘッダ類（8 mm）→デカップリング（裏面）→バルク（11 mm）の順。

**デカップリング100 nFは裏面に直付けする。** 各ICの3番（GND）と6番（VDD）のランドを裏側で橋渡しする形にすると、表面の穴を消費せず、しかもGND–VDD間のループが最短になります。TC4427の出力は数十nsで切り替わり瞬間的に約92 mAの電流ステップが出るため、この最短ループが効きます。

### R-Cペアの検品（貼り付け前に必須）

アルミに貼ると剥がせないため、**貼る前に16組すべてを電気的に検査する**。ペアの2本の自由端だけで測れるので、絶縁した接合点に触る必要はない。

```
Pico GPIO ──[120Ω]──┬── ペアの抵抗側リード
                     └── Pico ADC
Pico GND ─────────────── ペアのコンデンサ側リード
```

3.3 V駆動なのでノードが3.3 Vを超えず、分圧なしでADCに直結できる。GPIOをHIGHにした瞬間の立ち上がりを等価時間サンプリングで撮り、τを求める。

| 症状 | 原因 |
|---|---|
| 一瞬で3.3 Vに到達（τ≈0） | イモハンダ・断線 |
| 低い電圧のまま上がらない | コンデンサ短絡・リード同士の接触 |
| τが他と大きく違う | 容量値の取り違え |
| 開始電圧が違う | 抵抗値の取り違え |

τの絶対値ではなく**16組の間の外れ値**を見る。1組30秒程度。

## 9. QRNG APIについて — 熱力学的な妥協点の明示

APIで始める判断は妥当です（ハードウェア自作は詰まると全体が止まる）。ただし、前回議論した「支払いの強制」の観点で1点だけ弱点があります。

**$r$ がANUのサーバとネットワーク経路上に存在してしまう。** 厳密には、$r$ を知る観測者にとって $S(M|r)=0$ となり、段階Ⅱの下限が原理的には消えます。

**低コストな補強策**: RP2040内蔵のリングオシレータ由来ランダムビット（`ROSC_RANDOMBIT` レジスタ）と、API由来のQRNGを**XORして使う**。

$$r = r_{\text{QRNG-API}} \oplus r_{\text{ROSC}}$$

こうすると、$r$ の全体を知る主体は宇宙のどこにも存在しなくなります。ANUは $r_{\text{ROSC}}$ を知らず、$r_{\text{ROSC}}$ は装置内の熱雑音由来で記録されない。**追加部品ゼロ、コード数行**で、「装置外部に $r$ の purification が存在しない」という主張が回復します。

そして $r_{\text{ROSC}}$ は装置自身の熱浴のゆらぎ由来なので、前回話した「記憶を壊す熱と、手が感じる熱が同一である」という筋にも接続します。将来APD-QRNGに差し替えるとしても、このXOR構造はそのまま残す価値があります。

---

**未検証**: $\tau$の実測は5V駆動で行っており、12Vでは$R_{on}$が下がって値が変わる。$R$と$C$を分離できていないため総散逸は1.0〜1.1 Wの幅を持ち、確定にはINA260の実測が要る。掌側熱伝達係数（200 W/m²K想定、実際は50〜300 W/m²Kの幅）と接触窓12 mm角の妥当性、および0.9 mm厚での板と窓の温度差（概算1.0 K）はいずれも実機で未確認。4節の42℃ハードカットと40℃デューティ制御は、これらの不確実性を吸収する前提なので省略しないこと。
