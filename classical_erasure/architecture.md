# 熱破壊回路（FR-12）アーキテクチャ仕様書

**改訂日**: 2026年7月28日　**対象機能**: FR-12 熱破壊回路（炉の芯、コンデンサ対による物理実装）
**関連文書**：部品表・最終選定値・調達計画は`components.md`、設計変遷の経緯は[[熱破壊再考察]]、機能要件は`01_requirements/Functional_Req.md` FR-12を参照。部品点数・筐体サイズの検討課題は[[enclosure_fit_review]]、情報層部品の解説は[[info_layer_components]]、消去セルの部品選定根拠は[[erasure_cell_capacitor_choice]]、消去プロトコルの選定根拠は[[erasure_protocol_choice]]、セル駆動段を74HCT595からTC4427に変更した経緯は[[cell_driver_choice]]を参照。

## 1. 概要

FR-12は、消去処理そのものを担う専用回路を、ビットごとの相補コンデンサ対の充放電として物理的に実装する。設計目標は次の1点に集約される。

> 発熱量が、消去したビットの中身・部品の個体差・温度変化のいずれにも依存しないことを、較正ではなく回路トポロジー（$W=\tfrac12CV^2$の物理法則）によって保証する。

これにより「データが消える場所」と「熱が発生する場所」が同一の物理素子（コンデンサ＋抵抗）に一致し、FR-06（発熱演出）が実現しようとしている「発熱は演出ではなく実際の消去過程である」という主張を、回路構造そのものによる実証にする。

## 3. 機能ブロック

### 3.1 情報層（Raspberry Pi / Pico）

| 項目 | 内容 |
|---|---|
| 役割 | ネットワーク通信・MQTT・乱数取得（Pi）／4相タイミング生成・セル駆動（Pico） |
| Raspberry Pi の制約 | 平文はRAM上のみに保持（`tmpfs`）。`swapoff -a`必須。ログ・キャッシュへの書き出し禁止 |
| Pico の役割 | PIOによる4相サイクルの決定論的タイミング生成。乱数のバッファ非保持（4.6節参照） |

### 3.2 熱破壊セル（相補コンデンサ対）

| 項目   | 内容                                                       |
| ---- | -------------------------------------------------------- |
| 構成単位 | 1ビット＝コンデンサ2個（$C_b$, $C_{\bar b}$）＋直列抵抗2個（$R_\text{ext}$） |
| 駆動   | TC4427（デュアルMOSFETドライバ）の出力ピンが直接コンデンサの充放電を行う（専用スイッチ素子は不要）。Picoの空きGPIO本数の範囲内では直結でき、シフトレジスタは不要（規模がその範囲を超える場合のみ必要。[[cell_driver_choice]]参照） |
| 設計原理 | 4.2〜4.4節                                                 |

### 3.3 熱層（接触プレート、筐体スタック最下段）

| 項目 | 内容 |
|---|---|
| 構成 | 抵抗をアルミプレートに熱伝導接着し、断熱材で周囲を覆う。露出は底面の接触窓のみ。部品自体は基板全面に分散配置してよい（アルミの熱拡散が消去セッションの時間スケール内に基板全体を均すため、窓の近くに寄せる必要はない） |
| 設計根拠 | 抵抗で発生した熱がフォノンとして直接プレート・掌へ伝わる因果鎖を、翻訳段なしに保つため |
| 数値パラメータ | components.mdの熱設計節を参照 |

### 3.4 計測・安全層

| 項目 | 内容 |
|---|---|
| 構成 | NTCサーミスタ → コンパレータ → Pch MOSFET（セル電源のみ遮断） |
| 設計原則 | **安全系はファームウェア経由にしない**。ハードウェアのみのループで遮断できることを必須とする。ソフトウェア側の閾値はこれより低く設定し、ハードカットを最後の砦とする二段構え |

## 4. 動作原理

### 4.1 素子の役割定義

| 素子 | 役割 |
|---|---|
| GPIO／TC4427出力ピン | 2値の電圧源（$V$ または GND）として動作する唯一の能動部品 |
| コンデンサ $C$ | ビットの物理的実体。電荷の保持により状態（0/1）を表現する |
| 抵抗 $R_\text{ext}$ | エネルギー散逸素子。充放電エネルギーの一部がここで熱に変換される |

### 4.2 充放電エネルギーの中身非依存性（設計の核）

電源$V$から抵抗$R$を通してコンデンサ$C$を満充電するとき、電源が供給するエネルギーは$QV=CV^2$、コンデンサに蓄積されるのは$\tfrac12CV^2$である。差分の$\tfrac12CV^2$は抵抗で熱として散逸する。

$$W_\text{熱} = \tfrac12 CV^2 \qquad (R\text{に依存しない})$$

放電時も同様に$\tfrac12CV^2$が熱になるため、1回の充放電サイクルで$CV^2$が熱に変換され、その量は$C$と$V$のみで決まる。

**設計上の帰結**：
- 抵抗の個体差・温度依存性が熱量に影響しない
- 対称性が較正ではなく物理法則によって保証される（WDDL的な配線容量マッチングが不要になる根拠。経緯は[[熱破壊再考察]]参照）

### 4.3 ビット表現（相補ペア）

1ビットをコンデンサ2個の対$(C_b, C_{\bar b})$で表現し、常にどちらか一方のみが充電された状態を取らせる。

$$\text{ビット}=1 \;\Rightarrow\; (C_b\text{充電}, C_{\bar b}\text{放電})\qquad \text{ビット}=0 \;\Rightarrow\; (C_b\text{放電}, C_{\bar b}\text{充電})$$

ビットの値は「どちらが充電されているか」で表され、「充電されている個数」には依存しない。したがって値によらず、1遷移で動くコンデンサは常に1個であり、発熱量は値に依存しない。

### 4.4 4相動作サイクル

1ビットあたり、以下の4相を固定順序で実行する。

| 相 | セル状態遷移 | 備考 |
|---|---|---|
| 投入 | $(0,0) \to (d,\bar d)$ | 記憶ビット$d$を保持 |
| 消去 | $(d,\bar d) \to (0,0)$ | 装置内から$d$が消える |
| 攪拌 | $(0,0) \to (r,\bar r)$ | 乱数$r$で充電 |
| 鎮静 | $(r,\bar r) \to (0,0)$ | $r$を放電し標準状態へ戻す |

各相の間に必ず$(0,0)$（両コンデンサ放電状態）を経由させる。これを省略し$d$から$r$へ直接遷移させると、$d=r$の場合に発熱がゼロになり、対称性が中身に依存してしまう。$(0,0)$を経由させることで、$d$・$r$の値によらず4相すべてで必ずちょうど1個のコンデンサが動作し、

$$\alpha = 4 \times \tfrac12 CV^2 = 2CV^2 \quad [\text{J/bit}]$$

が回路の形だけで保証される。

### 4.5 外部出力制約

MQTTで外部へ送出する情報は攪拌後パターン・消去ビット数・実測熱量・経過時間のみに限定し、投入相の$d$そのものは一切外部に出さない。投入相の$d$を外部に出すと、記憶が冗長にコピーされ、消去前のデータが別のチャネルを通じて実在の領域に残ることになる。

### 4.6 ランダウアの消去段階との対応

| 相 | ランダウアの段階 |
|---|---|
| 消去 | 圧縮（多対一写像）。ただし直前状態$(d,\bar d)$は$d$を知る主体にとって既知であり、リセットに原理的コストはない |
| 攪拌 | 段階Ⅰ：障壁を下げ、誰にも既知でない状態を作る |
| 鎮静 | 段階Ⅱ：真のランダウア消去。直前状態$(r,\bar r)$は装置のどこにも記録されていないため、$Q\geq k_BT\ln2$の支払いが無条件に強制される唯一の段階 |

この帰結として、**乱数$r$をいかなる場所にもバッファ保持してはならない**。$r$が装置内外を問わずどこかに残れば、それを持つ主体にとって支払いが免除される。$r$の唯一の居場所は熱破壊セルそのものであり、鎮静相の実行と同時に記憶データと乱数が消える設計とする。

## 5. インターフェース仕様

| インターフェース | 信号線数 | 内容 |
|---|---|---|
| Pi ↔ Pico | UART/SPI | 乱数$r$・4相トリガー・NTC実測値の受け渡し |
| Pico ↔ TC4427 | セル数×2本（GPIO直結） | Picoの空きGPIO本数（概算18〜20本）まで直結可能。それを超える場合はシフトレジスタ経由に戻る（[[cell_driver_choice]] 3.5節） |
| TC4427 ↔ 熱破壊セル | セル数×2本 | 各セルの$C_b$・$C_{\bar b}$を個別に駆動 |
| NTC → コンパレータ | アナログ1系統/センサー | 計測・安全層。ファームウェアを経由しないハードウェアループ |
| コンパレータ → MOSFET | デジタル1本 | セル電源のみを遮断（Pico/Piの電源系統とは分離） |

## 6. 動作シーケンス

```
① 記憶装置投入・消去対象選択（FR-01/FR-05）
   ↓
② Piが乱数rを取得（FR-03のチェーンに従う）、平文をRAM上のみに保持
   ↓
③ 参加者が装置底面の接触窓に触れる（この時点でプレートは室温）
   ↓
④ Piがデータをブロック単位でPicoへ送信
   ↓
⑤ Picoが各ブロックに対し4相サイクル（投入→消去→攪拌→鎮静）を実行
     - サイクルはPIOにより一定周期で反復
   ↓
⑥ 全ブロック処理完了後、Pi側RAMバッファも上書き。セルは(0,0)標準状態に戻る
   ↓
⑦ 次の参加者を受け入れ可能な待機状態へ
```

参加者体験としての意味づけ（「冷たいプレートが体温を横切って温かくなる」等）はFunctional_Req.md FR-06・FR-10を参照。本節は電気的な動作順序のみを扱う。

## 7. 設計パラメータ

| 記号 | 意味 |
|---|---|
| $V$ | セル駆動電圧 |
| $C$ | セル容量（$C_b = C_{\bar b} = C$） |
| $R_\text{ext}$ | セル直列抵抗（駆動段の内部抵抗と合成される） |
| $\tau = RC$ | 1遷移あたりの時定数 |
| 1サイクル時間 | $16\tau$（4相×4$\tau$、フル充放電相当の時間を確保する場合） |
| $\alpha = 2CV^2$ | 1ビットあたりの理論散逸エネルギー（4.4節） |
| セル数（並列ビット数） | 総散逸電力・スループットを決定する主要な自由度 |

**設計原則**：$V$・$C$・$R_\text{ext}$の変更は対称性（中身非依存性）には影響しない。対称性は回路トポロジー（4相サイクル・相補ペア）のみに依存するため、これらの値は対称性を崩さずに独立に選んでよい。

**ただし総発熱量への効き方には注意が必要**：本設計は各フェーズで確実に$4\tau$待って完全充放電する（本節「1サイクル時間」参照）ため、サイクル周波数は$f=1/(16\tau)=1/(16RC)$と$C$に反比例して決まる。総散逸電力は

$$P = N_{bit}\times\alpha\times f = N_{bit}\times 2CV^2\times\frac{1}{16RC} = \frac{N_{bit}V^2}{8R}$$

となり、**$C$は式から消える**。つまり$C$を変えても総発熱量は変わらず、サイクル速度（＝スループット）だけが変わる。総発熱量を左右できるのは実質$N_{bit}$（並列ビット数、＝基板規模）と$V$（駆動段の耐圧上限まで）のみであり、$R_\text{ext}$も3.3節の設計根拠（抵抗をアルミ板上に置くことで熱源とデータ消滅点を一致させる）から下げる方向には動かせない。**熱設計（体感できる発熱量）を調整する自由度は、実質的にビット数・$V$（駆動段の耐圧上限まで）・接触窓の面積の3つ。**駆動段に電圧の伸び代がある場合（[[cell_driver_choice]]参照）、$V$が最も安価なレバーになる。

現在の選定値・セル数・総散逸電力・スループット等の確定値は`components.md`を参照（本書では重複を避けるため記載しない）。

## 8. 設計不変条件

以下はいずれも作品の理論的一貫性を支える不変条件であり、削ると設計の主張が成立しなくなる。

| 不変条件 | 崩した場合の帰結 |
|---|---|
| 相補ペア（1ビット＝コンデンサ2個） | 熱が中身に依存し、消去が「破壊」でなく「移動」になる |
| 4相サイクル（毎回$(0,0)$を経由） | $d=r$のときに発熱が消え、対称性が崩れる |
| 乱数をバッファに溜めない | $r$を知る観測者が生まれ、$k_BT\ln2$の支払いが免除される |
| 平文をRAMにしか置かない（tmpfs・swapoff） | 冗長コピーが残り、消去が完了しない |
| 安全系はハードウェアのみで完結させる | ファームウェアのハングが安全機構の無効化につながる |

## 9. 検証計画

| 検証項目 | 方法 |
|---|---|
| 対称性（中身非依存性） | オール0／オール1／QRNGの3パターンを同一ビット数消去し、プレートNTCの時系列を重ねる。3本が重なれば実証成立 |
| 線形性 | データ量を2倍・4倍にして総散逸熱量とビット数の直線性を確認する |
| 熱量の実測保証 | 電力計（INA260等）による$\int VI\,dt$の実測積算 |
| 安全機構 | ソフトウェア閾値・ハードウェアコンパレータの双方を、意図的な異常系（ファームウェアハング等）で個別に検証する |

段階的なビルド計画（試作→拡張→統合の手順とスケジュール）は`components.md`の発注順序節を参照。本書では検証項目のみを扱う。
