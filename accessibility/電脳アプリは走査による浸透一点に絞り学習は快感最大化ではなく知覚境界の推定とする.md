# 電脳アプリは走査による浸透一点に絞り学習は快感最大化ではなく知覚境界の推定とする

## 要約

忘却炉の熱を脳で受け取るアプリが何をするかを決めた。やることは一つだけで、消去が進むにつれて温かさが身体を少しずつ移っていく感覚を作る。同時に何ヶ所も温めると事前の測定が現実的な時間で終わらないため、温める場所は常に一ヶ所だけとし、順に移していく。アプリが利用者から学ぶのは「どう感じたか」の境目だけで、気持ちよさを最大にするような学習はしない。

## 機能を一点に絞る

[[FR-11感覚配信における忘却炉と電脳側の処理境界]]のLayer3が担うのは体験の設計であり、[[電脳OSが担う責務の範囲]]が「OSにできないこと」として挙げた表現の設計・意味の解釈・レンダリングインテントの宣言がそのまま職域になる。ここに置く機能を、**消去の進行に応じて温感が身体を移っていく提示**の一点に絞る。前線の位置は忘却炉が送る抽象イベントのうち累積散逸エネルギーと理論総エネルギーの比、すなわち処理進捗から駆動する。

一点に絞れるのは、この機能が要求する較正がきわめて薄いからである。[[較正データへのアプリアクセスの段階設計]]が機微度と有用性の逆相関を示した表に照らすと、必要なのは電極と知覚部位の順序関係と間隔比だけで、絶対ラベルも閾値もafter-discharge閾値も要求する理由がない。同ノートが第1段階の説明に用いた「四肢から前腕、体幹へと広がる表現を設計するのに要るのは並び順と間隔比だけ」という例と、この機能は一致する。したがってパターン記述をOS側で実行する既定の経路だけで足り、**開示は第1段階の不透明トークン列すら発生しない**。

**進行を空間に載せるのは、強度には載せられないからである。** 忘却炉の接触プレートは40℃デューティ制御下にあるため、1 MB（約157秒）のセッションで温度は立ち上がりの約37秒を過ぎると平坦になり、以降は消去の進行ではなくサーモスタットの動作を表す。加えて[[接触プレートの42℃上限と体感を決める接触条件]]が引くKenshaloの臨界レート0.1℃/秒により、緩やかな昇温そのものが知覚されにくい。強度をじわじわ上げる設計は順応と臨界レートの両方に負ける。一方、提示部位を移し続ける設計では常に未順応の部位を刺激することになり、順応が不利ではなく有利に働く。

ただし**これは再現ではなく発明である**ことを設計の前提として明示する。[[architecture]]の通り接触プレートはアルミの熱拡散により空間的に一様で、生身の参加者は空間的な浸透を体験していない。アプリが作るのはモダリティ間の翻訳であって、掌の感覚の忠実な移植ではない。段階設計ノートが表現の発明権をアプリ側に残すべきとした対象がまさにこれであり、正当な行使だが、忠実性を装ってはならない。FR-11ノートが「忘却炉は忠実な再現を前提にしてはならない」と定めた非対称が、アプリの側にも同じ形で現れる。

## 同時提示を却下し走査に限る

浸透の実装には、点灯済みの区間を保持したまま前線を伸ばす**同時提示**と、前線だけを移す**走査**の二案がある。**走査を採用する。**

却下した同時提示の問題は交差項の較正費用である。[[基礎較正の欠如は拒否ではなく能力ネゴシエーションで扱う]]の見積もり（1量あたり約1分）で、軸をN段のゾーンに分けたときの全ペア較正はN²/2に比例し、N=16で約2.1時間、N=32で約8.5時間かかる。浸透が点灯するのが連続区間に限られるならば測定対象は区間長ごとの実効強度だけとなり必要数はN個へ落ちるため、同時提示も不可能ではない。それでも走査を採るのは、交差項を定義上ゼロにできること、軸の段数が2しかないコールドスタート時点でも成立すること、そして順応への耐性が同時提示より高いことによる。基礎較正ノートが「相互作用は測らずに禁じる」として調停に見出した第二の効用を、アプリ側でも同じ理由から自主的に採る形になる。

代償は、ゾーン間の受け渡しが重なりのないハード切り替えになることである。空間的なクロスフェードは交差項を呼び戻すため使えない。したがって**連続性を作る手段は時間パラメータだけに限られる**。離散的な刺激列が適切な時間間隔で連続に知覚されうることは仮現運動として知られるが、温感の走査で同じことが成り立つかは本ノートでは確認していない。この一点にアプリの難所が集中する。

## OSに置く仮定

OSの詳細が後から変わっても設計が生き残るよう、前提を次の5点に限る。

| 仮定 | 内容 |
|---|---|
| 軸 | 順序付いたN個のゾーンがあり、一度に1つ、温感を焚ける |
| 強度 | 0.0〜1.0で表され、1.0が安全上限。絶対値は知らないし知れない |
| 時間 | 自由に決められるが安全予算は有限で、セッション開始前に全長を予約する |
| 応答 | 返らない。知覚されたかの確認手段はなく、完全なオープンループである |
| 適応 | アプリ所有の適応データはOSに預け、世代番号が変われば自分の適応値を捨てる |

**設計の規律としてより重要なのは、仮定してはならない4点のほうである。** ゾーン数Nを固定値と仮定しない。N=2でも成立しNが大きければ滑らかになる形で書き、コールドスタートはN=2から始まるものとして扱う。ゾーンの絶対位置を仮定しない。「前腕」「肩」と名前で呼んだ時点で開示ゼロの前提が崩れ、[[基礎較正の欠如は拒否ではなく能力ネゴシエーションで扱う]]が指摘する通り集団統計による事前分布も部位には効かないため、あるのは順序と間隔比だけである。刺激が届いたと仮定しない。確認が返らない以上、進行の管理はアプリ内部の時計で持つほかない。そして**セッションが最後まで走ると仮定しない**。予算切れ・利用者による物理遮断・OSによる中断がつねにありうるため、儀式は途中で終わっても成立する形にしておく必要がある。最後の一点はFR-10の儀式設計に直接跳ね返るが、その具体は本ノートの範囲外である。

## OSへ新たに要求する三点

以上のうち三点は、既存ノートのどこにも記述がない新規の要求である。

**期間を伴う予約。** 忘却炉のセッションは総散逸エネルギーが開始前に確定しており（ビット数×18.9 µJ）、所要時間も1 MBで約157秒と既知である。予算切れによる中断が儀式の途中で起きるとFR-10が根本から壊れるため、アプリは開始前に全長分の安全予算を予約できなければならない。[[電脳OSが担う責務の範囲]]がOSをウィンドウマネージャと見なして置いた排他ゾーンのアロケータには、期間を伴う予約という概念がまだない。

**日和見較正の抑止宣言。** 基礎較正ノートは知覚地図を育てる手段として、通常利用に相乗りして較正する日和見較正を挙げる。専用の較正セッションと違って追加の電荷も時間も払わずに済む優れた仕組みだが、成立にはOS所有のUIが利用者へ問いを差し込む必要がある。同ノート自身が「アプリの体験を壊さずに成立するかも未検証」と留保している通りで、葬儀として設計された儀式の最中にこれは差し込めない。したがってアプリがセッション単位で日和見較正を抑止できる必要があり、抑止した分の較正機会は儀式前段に置く調律フェーズで取り返す。

**世代番号への補正モデルの版の包含。** [[アプリ固有の較正データはアプリが所有しOSが保管する]]は、基礎較正が引き直されると適応値が黙って間違いになるとして世代番号を要求した。同じ破綻はOS側の順応補正モデルが更新されたときにも起きる。FR-11ノートの通りアプリが観測する反応はOSの圧縮・クリップ・順応補正を経た後のものであり、アプリの適応値は補正後の残差に対して調律されているためである。世代番号は較正テーブルの世代だけでなく補正モデルの版も含む必要がある。

## 学習は境界推定に限る

アプリが利用者から学ぶ対象を、**意図した知覚が起きたか否かの境界**に限定する。走査に限定した結果、最重要のパラメータは前線がゾーンを移る時間間隔ひとつに集中している。適応ノートが選好に対する適応の例として挙げた「800 msの走査は広がりに感じられるが400 msでは跳んだに感じられる」がそのまま推定対象であり、探すべきものがピークではなく**境界**であることをこの例自身が示している。手法は心理物理の適応的階段法とし、基礎較正ノートと同じ25試行程度の規模を見込む。

**却下したのは、神経応答を報酬として快感・没入が最大になる提示パターンを機械学習で探索する案である。** 理由は三つある。

第一に、責務の範囲ノートは「技術的に安全域内でありながら心理的に強要的なパターンを検出することはできない」ことをOSの原理的な限界として挙げ、皮質への直接書き込みには目を逸らすという末梢の逃げ道がないと指摘している。没入最大化はこの検出できないものを目的関数として明示的に構築する行為にあたり、Layer4もLayer5も一度も発火しないまま最適化が進む。報酬信号を脳から取る以上、閉ループが利用者の身体の内側で閉じ、逃げ道がないという指摘がそのまま効く。

第二に、装置の主張と逆を向く。[[idea]]が提案するのは実在の証明ではなく執着の放棄であり、没入最大化ループは執着の生成装置である。葬儀は快感を最大化する装置ではない。

第三に、適応ノートが「適応的な探索を繰り返すこと自体が、差分的な推定によって対応表の構造を部分的に再構成する経路にもなる」として探索回数の上限を未決の課題に挙げている。能動探索を伴う最適化はこの差分プロービングの最悪ケースであり、開示ゼロで組んだ設計が探索の側から迂回される。

倫理的な理由を措いても実務的に成立しない。1セッション157秒でN=8の走査なら意味のある報酬は8サンプル程度しか得られず、強化学習には桁が足りない。しかも試行を増やすには電荷予算と電極摩耗を払い、実際に消去する記憶と参加者を要するため、データ収集を回せる対象ではない。

ただし**神経応答を読むこと自体は採用する。** 「感じ取れたか」には刺激に時間同期したイベント単位の確認と、刺激間で測れる遅い集約状態の二種類があり、前者は責務の範囲ノートの通り刺激アーティファクトが同時記録を妨げること、および誘発電位が意識的な知覚と同一でないことから成立しない。後者は時間同期を要さず知覚されたとも主張しないため成立しうる。これを**最大化の報酬ではなく逸脱の検出に使う**——集中が崩れたなら儀式が機能していないので静かに畳む、という停止条件として扱う。監視には使うが最適化はしない。この形であれば申告UIを差し込まずに調律フェーズを成立させられるため、応答を読む価値はむしろこちらにある。なおアプリは読み取り方向で生の神経データに触れられないため、OSが導出済みのスカラーとして返す形を前提とする。

## 未検証

温感の走査において離散的な前線の移動が連続した浸透として知覚されるかは確認していない。仮現運動からの類推であり、温度知覚で同じ時間窓が成り立つ保証はない。走査を採った代償がここに集中しているため、この一点が崩れると機能そのものが成立しない。

交差項の較正費用の見積もりは基礎較正ノートの1量あたり約1分という仮定をゾーン空間へ持ち込んだものだが、同ノート自身がこの数字を文献に当たっていない仮定としている。したがってN=16で2.1時間という値も桁の目安に留まる。

軸の段数Nが実際にいくつになるかの見当がついていない。N=2でも成立する形に書くとしているが、Nが小さいときの浸透が体験として成立するかは未検証であり、成立しない下限が存在する可能性がある。

集中度に相当する遅い状態を、刺激と並行してどの精度で取得できるかは未確認である。刺激アーティファクトの影響がイベント単位の確認ほど深刻でないという判断も推論に留まる。またこの状態量がプライバシー上どう扱われるべきかは検討しておらず、[[神経データのプライバシー保護の現状]]が挙げる神経データの定義に含まれるかも確認していない。

期間を伴う予約・日和見較正の抑止宣言・補正モデルの版という三つの新規要求は、いずれも既存のBCI基盤に対応物を確認していない。[[BCI用ソフトウェア基盤の実装状況]]が示す通り既存基盤は単一アプリ前提であり、調停を担う層自体が実在しないため、これらの要求は未成立の前提の上に重ねられている。

儀式が途中で終わっても成立する形をどう作るかは本ノートでは扱っていない。FR-10の儀式設計側の課題として残る。
